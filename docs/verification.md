# 验证方法与标准

Generated by: GPT-6 (Codex)

从仓库根目录执行。`install.sh --check` 必须在缺少必要命令时返回非零，并且不写目标目录。
`scripts/verify.sh` 和 `scripts/test.sh` 必须全部通过，不能只用 `zsh -n` 判断交互正常。

| 检查 | 工具与通过标准 |
| --- | --- |
| 入口和语法 | `readlink`、`bash -n`、`zsh -n`；入口解析到本仓库，语法无错误 |
| Zsh 加载 | `script` 提供伪终端，启动交互 Zsh；正确仓库、建议/高亮函数、Ctrl-R/Ctrl-X Ctrl-E 按键绑定均存在 |
| zoxide | `j`/`ji` 对应 zoxide，目录钩子只注册一次；实际跳入带空格目录 |
| Vim | 无界面启动，确认 Files/Rg/Buffers、原有插件命令和映射存在；两次进程验证持久撤销 |
| 文件查找 | fdfind/fd、fzf、rg 能处理中文及空格路径；遵守 `.gitignore`，排除 `.git` |
| 安装 | 临时 home、含空格仓库路径；首次安装成功，再次安装不产生链接变更 |
| 回滚 | 恢复原文件、目录、失效符号链接；删除新链接；遇到后续修改时整次拒绝 |
| tmux | 独立 socket 启动，检查窗口起始编号、鼠标和 vi 复制模式，不连接现有会话 |

`test.sh` 用临时目录及本机已有插件作为缓存，离线 clone Zsh 插件，复用 Vim 插件和 fzf
下载文件。成功后清理临时目录；失败时输出保留路径。它不检验 GitHub 的网络可达性，
也不能替代不同架构服务器上首次下载 fzf 的验证。运行前先完成一次安装。

交互验收还需要在实际终端中执行：

1. 新开 Zsh，输入一条可识别的命令；按 Ctrl-R，找到它并取消或选回命令行。
2. 用 Ctrl-T 找含空格的文件，确认插入路径转义正确；用 `ji` 搜常用目录。
3. 打开 Vim：`<Space>ff` 选文件，`<Space>fg` 输入文本，选中结果后确认文件和行号。
4. 用现有 tmux 前缀（默认 Ctrl-B）分屏、切换、进入复制模式，确认终端按键体验。

当前 Vim 编译为 `-clipboard`，设置 `unnamedplus` 不会凭空提供系统剪贴板。
这项不算安装失败；需要系统剪贴板时再单独选择带支持的 Vim 构建或明确的 WSL 集成方案。

实验个人配置时，可复制仓库到临时目录，并选择临时 home：

```sh
scratch=$(mktemp -d)
mkdir "$scratch/home"
cp -a ~/.dotfiles "$scratch/repo"
DOTFILES_TARGET_HOME="$scratch/home" "$scratch/repo/install.sh" --apply
vim "$scratch/home/.zshrc.local"
env HOME="$scratch/home" ZDOTDIR="$scratch/home" zsh
```

`DOTFILES_TARGET_HOME` 控制安装目标；正常安装时无需设置。这里复制仓库是为了避免通过
同一个源码链接改到真实环境；仅另开一个 Zsh 窗口不能隔离仓库文件修改。
实验会保留目录，退出后自行确认再清理。
